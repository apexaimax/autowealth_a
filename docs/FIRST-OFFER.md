# First Revenue Offer — Repository Release Verification

## Buyer
Solo developers and small teams preparing a GitHub release, especially browser extensions and small web/TypeScript projects.

## Promise
An evidence-backed release verification report based on the buyer's public GitHub repository. No source-code upload or repository access is required for public repos.

## Deliverable
- version/release consistency check
- package/manifest/release artifact reconciliation when present
- CI/test status check
- changed-file and release-path review
- obvious packaging/configuration blockers
- concise findings grouped as verified / needs buyer verification / blocker
- final release checklist

## Boundaries
This is not a penetration test, legal compliance audit, or guarantee that software is bug-free. Private repositories require an explicitly authorized access path and are not part of the zero-friction starter offer.

## Starter pricing hypothesis
First-customer offer: **$15 prepaid** for one public repository and one release target.

This price is a market experiment, not realized revenue. Platform/payment fees must be deducted when calculating actual P&L.

## Acceptance criteria
A job is complete when the buyer receives the report and every factual repository claim is traceable to public repository evidence observed during the review.
